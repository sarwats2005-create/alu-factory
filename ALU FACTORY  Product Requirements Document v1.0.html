ALU FACTORY — Product Requirements Document (PRD)

Version 1.0 | Erbil, Iraq

1. PRODUCT OVERVIEW

Product Name: ALU FACTORY
Company: ALU FACTORY
Type: Full-stack, fully responsive ERP web application
Primary Language: English | Secondary Language: Kurdish Sorani (کوردی سۆرانی) with automatic RTL layout
Currencies: USD (primary) + IQD (secondary) with configurable exchange rate
Platform: Web browser — desktop and mobile equally supported

Purpose

ALU FACTORY is a production-grade ERP system purpose-built for aluminum factory operations. It replaces manual Excel/paper workflows with a modern, accurate, and fully integrated platform covering: raw material purchasing, inventory management, production loss tracking, point of sale, customer and beneficiary account management, dual-currency vault control, profit & loss reporting, and role-based access control.

8. INVENTORY MODULE

Tracks all raw aluminum stock from purchase through to processed/available state.

Stock Entry (from Beneficiary Purchase)

  • Every purchase from a beneficiary automatically creates or updates an inventory item
  • Item fields: Name, SKU Code, Aluminum Type, Total Weight Purchased (kg), Beneficiary Source, Date In

Loss Process

When raw material is processed/fabricated:

  • User opens inventory item → clicks "Process / Apply Loss"
  • Loss Entry Options:
    • Option A — Percentage: Enter loss % → system shows live preview below field: "Result: 920 kg available after 8% loss"
    • Option B — Manual: Enter exact remaining weight directly
    • Both options available — user chooses per batch
  • System records: Original Weight, Loss Amount, Loss %, Remaining Weight, Date Processed
  • Processed item becomes available in POS module under same Name + SKU

Inventory List

  • Columns: SKU, Name, Type, Total In (kg), Loss Applied, Available (kg), Status (In Stock / Low / Out)
  • Low stock alert triggers when available weight drops below threshold (configurable in Settings)
  • "Restock" button on any item → opens new Beneficiary Purchase form pre-filled with that item

Inventory Movement Report

  • Full history: purchases in, losses applied, sales out, remaining balance per item
  • Exportable as PDF/CSV

  • Withdrawal: Remove money from a vault — recorded with date, note, and reason label

  • Owner/authorized user sets exchange rate: 1 USD = X IQD

  • Editable at any time — change is logged with timestamp

Vault Transaction History

  • Full log of every movement: purchases, sales, deposits, withdrawals, exchanges

  • Filter by vault, date range, transaction type
  • Exportable PDF/CSV

Negative Balance

  • System allows vault to go negative (no hard block)
  • Negative balance displayed clearly in red with explicit label

13. CORE BUSINESS LOGIC & CALCULATIONS

Mandatory Auto-Calculations (never manual)

Purchase Total    = Weight (kg) × Unit Price
Sale Total        = Weight (kg) × Unit Price  
Due Amount        = Total − Cash Paid
Net Profit (sale) = Sale Total − (Weight × avg buy price per kg)
Overall P&L       = Sum(all sale totals) − Sum(all purchase totals)
Loss Result (kg)  = Original Weight × (1 − Loss% / 100)
Exchange          = Amount × Exchange Rate

Data Integrity Rules

  • Total Price is always recalculated server-side — never trusted from user input
  • Inventory deducted only on confirmed sale submission
  • Vault balance updated only on confirmed transaction submission
  • No transaction modifies data without full validation pass
  • Duplicate submission prevented via button state management

Due Balance Labeling (always explicit)

  • Customer side: "Customer owes factory"
  • Beneficiary side: "Factory owes beneficiary"
  • Never ambiguous, never unlabeled

14. TRANSACTION EDITING & DELETION

Editing

  • All transactions (purchases, sales, vault operations) are editable
  • Edit loads transaction into form — form switches to "UPDATE" mode
  • Clearly shows: "EDITING TRANSACTION #XXXXX" + Cancel button
  • On update: recalculates all dependent values, updates inventory and vault accordingly

Deletion

  • Requires confirmation dialog showing full transaction details
  • On delete: reverses inventory and vault effects
  • Cannot be undone — dialog makes this explicit

Audit Trail

  • Every edit and deletion is logged with: who did it, when, what changed
  • Owner can view audit log in Settings

17. PERFORMANCE & TECHNICAL REQUIREMENTS

  • Server-side pagination on all tables (default 25 rows, options: 50/100)
  • Server-side search and filtering — no client-side full-table loads
  • Debounced search (300ms) to prevent excessive queries
  • Proper database indexes on: date, customer_id, beneficiary_id, product_sku, invoice_number
  • All forms prevent duplicate submission (button disabled during processing)
  • Skeleton loading states on all data tables
  • Loading indicators on all async actions
  • Never silent failures — every error surfaces a clear, specific message to the user
